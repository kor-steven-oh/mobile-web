# SDD 2026

S.LSI Developer Day 모바일 웹앱. React, TypeScript, vinext 기반.

```sh
npm install
npm run dev
```

`npm run build`로 배포 빌드를 생성합니다.

- `/`: 시작 화면과 이름·휴대전화번호 로그인(`010` 고정, 뒤 8자리 입력, `0000-0000` 자동 표시 및 제출 전 확인)
- `/home`: 로그인한 이름의 인사말, 저장한 세션 중 아직 시작하지 않은 가장 이른 세션(KST 기준), 빠른 메뉴, 추천 프로그램
- `/program`: 5개 강연장 선택(1층: 101 AP, 107 CP / 2층: 201 LSI, 206 Sensor, 208 직속), 강연장별 세션 5개, 시간순 세션, 검색 및 상세 정보
- `/speakers`: 강연자 25명 가나다순 목록과 세션 상세
- `/event`: NFC 수강 인증, 참여선물 수령, 럭키드로우 응모
- `/mypage`: 이름·연락처 프로필, 저장한 세션, 로그아웃

행사는 2026년 10월 15일 오전 10시 The UniverSE에서 시작합니다. 강연 세션과 연사는 제공된 행사 정보이며, Home의 Lunch Concert는 제공된 사진을 경량화한 `public/concert.webp`과 12:00–13:00 공연 시간을 표시합니다. 출연진 이름과 상세 안내는 추후 반영합니다. `app/data.ts`에서 수정합니다. 이름과 휴대전화번호는 D1 서버 데이터베이스에 저장되고, 브라우저에도 프로필이 저장됩니다. 180일 동안 유효한 HTTP 전용 세션 쿠키로 재방문 시 자동 로그인됩니다. 번호 형식만 검사하며 문자 인증은 포함되지 않습니다. 북마크는 현재 브라우저의 localStorage에 저장됩니다. 이벤트 페이지에서 NFC 수강 인증과 참여선물 자격, 럭키드로우 응모권을 확인합니다. 참여선물은 STAFF 인증번호 확인 후 수령 완료로 기록합니다. 실제 추첨 실행 기능은 아직 포함되지 않습니다. `public/sdd-original.png`는 제공된 로고 원본입니다. Start에서는 원본 이미지의 SDD 심볼 영역만 비율 그대로 표시하고, 바로 아래에 Pretendard로 2026을 배치합니다.

기본 글꼴은 [Pretendard Variable](https://github.com/orioncactus/pretendard)의 공식 가변 다이나믹 서브셋 웹폰트(v1.3.9)를 사용합니다.

## Cloudflare Workers 배포

`vote2`와 같은 Cloudflare 계정에 독립 Worker `sdd-2026`으로 배포합니다. 이 앱은 vinext의 Workers 빌드를 사용하며, 배포 설정은 `wrangler.jsonc`에 있습니다. 로그인 정보는 별도 D1 데이터베이스 `sdd-2026-db`에 저장됩니다.

```sh
# 최초 인증 (이미 로그인되어 있으면 생략)
npx wrangler login

# 데이터베이스 스키마가 바뀐 경우 배포 전에 마이그레이션 적용
npx wrangler d1 migrations apply DB --remote --config wrangler.jsonc

# 빌드 및 배포
npm run deploy

# 배포 없이 빌드와 업로드 구성만 검증
npm run deploy:check

# 바인딩 변경 시 타입 재생성
npm run cf:typegen
```

빌드가 생성한 `dist/server/wrangler.json`을 배포에 사용합니다. 출력 파일을 직접 수정하지 마세요. 로컬 개발은 계속 `npm run dev`를 사용합니다. 기존 `.openai/hosting.json`은 Sites 배포 기록이며 위 명령은 Cloudflare 계정에 직접 배포합니다.

저장한 세션은 브라우저 및 사이트 주소별로 별도 저장되므로, localhost에서 저장한 항목은 배포 주소로 자동 이동하지 않습니다.

운영 주소: https://sdd-2026.slsi.workers.dev

### 참가자 식별과 데이터 연결

- `registrations`는 이름(앞뒤 공백 제거)과 숫자 11자리 전화번호의 조합을 UNIQUE로 관리합니다. 같은 조합의 재로그인·동시 요청은 기존 UUID `id`를 재사용합니다. 이름이나 번호가 다르면 별도 참가자입니다.
- 응모권, 세션 참석 인증, 추첨 결과를 구현할 때 `registrations.id`를 외래 키로 연결합니다. 클라이언트가 보낸 참가자 ID를 신뢰하지 말고 `currentRegistration(request)`로 확인한 ID를 사용해야 합니다.
- 기존 참가자 ID와 로그인 세션은 마이그레이션 후에도 유지됩니다. 스키마는 로그인 시 생성하지 않고 `drizzle/` 마이그레이션으로 관리합니다. 새 로컬 환경은 `npx wrangler d1 migrations apply DB --local --config wrangler.jsonc`를 먼저 실행합니다. 운영 배포 전에는 `--remote`로 적용합니다.
- 번호 확인창은 입력 실수 방지용이며 문자 본인 인증은 아닙니다. 같은 번호에 이름을 달리 입력하면 별도 참가자가 되므로, 번호 소유 확인이나 1인 1응모 제한은 실제 이벤트 구현 시 별도 정책이 필요합니다.

### NFC 수강 인증 / 보상 운영

- `event_sessions`에 행사일(2026-10-15 KST)의 25개 강연과 5개 시간대를 저장합니다. 현재 인증 가능 시간은 **시작 시각 이상, 시작 후 10분 미만**입니다. 이 운영 기본값은 `0002` 마이그레이션의 `closes_at`에 반영되어 있으며 운영 확정 후 별도 마이그레이션으로 변경합니다.
- 참가자가 입구의 URL NFC 태그를 읽어 `/event#checkin=...`을 열면 서버 세션의 참가자 ID로 인증합니다. 미로그인 시 태그 정보를 잠시 보관했다가 로그인 후 이벤트 페이지로 돌아와 인증합니다. 클라이언트에서 참가자, 강연, 시간, 인증 횟수를 지정할 수 없습니다.
- `attendance`의 `(registration_id, slot)` 기본키로 시간대별 1개, 총 5개를 강제합니다. 세션/시간대의 복합 외래 키로 잘못된 강연 연결을 막습니다. 중복 태깅은 기존 기록을 반환하고 같은 시간대의 다른 강연은 거부합니다.
- 2개 달성 시 `event_rewards.kind=gift`, 4개 달성 시 `kind=ticket`을 인증과 같은 트랜잭션에서 생성합니다. 참가자/종류 UNIQUE로 재시도·동시 요청에도 보상은 각각 1개입니다. `kind=ticket` 기록은 응모 자격이며, 실제 숫자 응모권은 버튼을 누를 때 별도 `raffle_entries`에 발급됩니다. `redeemed_at`은 STAFF 인증번호를 확인한 서버가 수령 완료 시 기록합니다.
- 프런트의 인증 상태는 `/api/attendance`로 읽습니다. localStorage의 프로필/북마크는 보상 판정에 사용하지 않습니다. 실제 추첨 기능은 추후 `raffle_entries`의 유효 응모번호와 참가자 ID를 기준으로 연결합니다.

NFC 태그 준비(운영 도메인 확정 후):

```bash
# 운영 서버에 스키마 적용 후 앱을 함께 배포
npx wrangler d1 migrations apply DB --remote --config wrangler.jsonc
# 새 폴더에 강연장별 URL 5개와 DB 등록 SQL 생성 (원본 토큰은 터미널에 출력하지 않음)
node scripts/create-nfc-tags.mjs https://sdd-2026.slsi.workers.dev .wrangler/nfc-production
npx wrangler d1 execute DB --remote --config wrangler.jsonc --file .wrangler/nfc-production/register-tags.sql
```

생성된 `tags.json`의 강연장별 URL을 해당 입구 NFC 태그의 NDEF URL로 기록합니다. 이 파일은 공개하거나 커밋하지 않습니다. DB에는 토큰 해시만 저장됩니다. 태그 교체 시 해당 `nfc_tags.id`의 `active`를 0으로 바꾸면 기존 URL을 폐기할 수 있습니다. 로컬에서는 `http://localhost:3001`과 `--local`을 사용합니다.

일반 URL NFC 태그는 링크 복사를 막거나 물리적인 현장 태깅 자체를 증명하지는 못합니다. 이 구현은 등록된 태그 URL·서버 시간·로그인·중복 제한과 행사장 반경 내 위치를 검사합니다. 브라우저가 제공한 좌표의 위조까지 방지하지는 못합니다. 현장 존재의 엄격한 증명이 필요하면 동적 인증 NFC 또는 운영자 확인 장치를 추가해야 합니다. 이름+전화번호 로그인 또한 문자 본인 인증은 아닙니다.

### 행사장 위치 확인

- 행사장 좌표는 제공된 [Google Maps 장소 링크](https://maps.app.goo.gl/Z6d8Dp8VkaqN8qnn6)의 삼성전자 The UniverSE 핀을 사용합니다: 위도 `37.2349187`, 경도 `127.0762349243164`.
- 서버 설정 `db/venue-config.ts`에서 허용 반경 200m, 최대 측정 오차 100m를 관리합니다. 브라우저가 보내는 반경이나 판정값은 사용하지 않습니다. 정확도 값을 허용 반경에 더하지 않습니다.
- NFC 인증할 때만 고정밀 현재 위치를 요청합니다. 캐시 위치는 사용하지 않으며, 서버는 60초가 지난 측정이나 서버보다 10초 넘게 미래인 측정을 거절합니다. 기기의 날짜/시간은 자동 설정을 권장합니다.
- 위치 권한 거절, 조회 실패·시간 초과, 반경 밖, 오차 초과에서는 인증하지 않고 재시도 안내를 표시합니다. 위치 실패 시 NFC 정보는 기존 10분 유효시간 내에서 유지됩니다. 인증 현황 조회에는 위치 권한이 필요하지 않습니다.
- 위치 좌표는 서버 판정 후 저장하거나 로그에 남기지 않습니다. 위치 체크를 생략한 직접 API 요청도 거부됩니다. 운영 환경은 HTTPS가 필요하며 HTTP localhost는 개발용으로 사용할 수 있습니다. 실내 실제 기기의 정확도·권한 동작은 현장에서 확인 후 반경/오차 기준을 조정하세요.

### 현재 임시 인증 설정

`app/attendance-policy.ts`의 `enforceLocation`과 `enforceTime`은 현재 **false**입니다. 위치 조회는 계속 시도하지만 비동기로 진행되어 권한 거부/조회 실패/거리/오차 때문에 인증이 멈추지 않습니다. 시간 조건도 검사하지 않습니다. 테스트 URL은 `/event#checkin=태그토큰&slot=1` 형식이며 slot=1~5로 시간대를 지정합니다. URL에 지정된 강연장과 회차가 자동 인증되고 이벤트 페이지에는 회차 선택 UI가 없습니다. slot이 없는 기존 URL은 1회차를 인증합니다. 로그인 전에도 토큰과 회차를 함께 보관합니다.

유효한 NFC 태그와 로그인, 시간대별 중복 방지 및 보상 중복 방지는 유지됩니다. 운영 조건을 복구할 때 두 설정을 true로 바꾸면 서버가 현재 강연을 시간으로 선택하고 위치를 필수 검사합니다. 위의 200m/100m/10분 규칙은 현재 비활성 상태입니다.

### 참여선물 STAFF 수령 처리

세션 2개 이상을 인증하면 참여선물 버튼이 활성화됩니다. 참가자가 버튼을 누르면 “STAFF에게 제출하세요” 팝업이 열리고, STAFF가 팝업에 4자리 번호를 입력하면 `/api/gift-redemption`에서 참가자 세션과 수령 자격을 확인한 뒤 `event_rewards.redeemed_at`을 기록합니다. 같은 참가자의 재시도나 동시 요청은 최초 수령 시각을 유지합니다. 럭키드로우 응모권 상태에는 영향을 주지 않습니다.

STAFF 확인 번호는 서버에서 `5555`로 고정합니다. 별도 환경변수나 입력 횟수/IP 제한은 없으며, 입력 시도·오입력 이력은 저장하지 않습니다. 수강 인증 2개 이상인 참가자에게 지급하며, `event_rewards.redeemed_at`에 수령 완료 시각을 기록합니다. 반복 요청은 기존 수령 완료 기록을 반환합니다. `0006` 마이그레이션은 과거 입력 시도 테이블만 삭제하고 수령 이력을 보존합니다.


### 럭키드로우 순번 응모권

4개 인증은 응모 자격만 부여합니다. 사용자가 **응모하기**를 누르면 `/api/raffle-entry`가 로그인한 참가자의 인증 횟수를 검사하고 `raffle_entries.number`를 1부터 순서대로 발급합니다. 참가자 ID는 UNIQUE이며 발급 검사와 INSERT는 같은 D1 트랜잭션입니다. 미자격 요청·중복 클릭·동시 요청은 번호를 소모하지 않고 기존 번호를 반환합니다. 사용자에게 UUID 대신 숫자 번호를 표시합니다.

### 별도 관리자 앱

관리자 페이지는 참가자 앱과 같은 주소의 `/admin`에서 열립니다. 로컬 개발 서버가 3001번 포트라면 `http://localhost:3001/admin`으로 접속하세요. 관리자 API는 `/admin/api/*`를 사용합니다.

관리자 화면과 인증 로직은 `admin/`에 있으며 별도 앱 실행도 지원합니다. 패키지 의존성은 루트 프로젝트를 공유합니다.

```bash
npm run dev:admin       # http://127.0.0.1:3003
npm run build:admin     # admin/dist/client + admin/dist/sdd_2026_admin
# 운영 배포 시 (로컬 작업에서는 실행하지 않음)
npx wrangler secret put ADMIN_PASSWORD_HASH --config admin/wrangler.jsonc
npx wrangler deploy --config admin/dist/sdd_2026_admin/wrangler.json
```

- 관리자 비밀번호는 요청받은 값의 SHA-256 해시로 루트 `.dev.vars`에 설정됩니다. 별도 앱은 `admin/.dev.vars`를 사용합니다. 파일은 Git에서 제외됩니다. 운영 Worker에는 별도로 Secret을 등록해야 합니다. `/admin` 운영 시 루트 설정으로 `npx wrangler secret put ADMIN_PASSWORD_HASH --config wrangler.jsonc`를 실행하세요.
- 관리자 세션은 참가자 로그인과 다른 HttpOnly 쿠키 및 `admin_sessions`를 사용하며 12시간 유효합니다. 로그인은 IP별 5회/15분, 전체 30회/15분으로 제한됩니다.
- 참가자 이름/전화번호 검색, 25명 단위 목록, 세션 인증 내역, 선물 수령/응모 상태, 변경 이력을 제공합니다.
- 세션 1개 인증 취소, 수강 인증 전체 초기화, 선물 수령 상태 초기화, 응모 취소, 전체 참여 기록 초기화가 가능합니다. 버튼을 누르면 확인창·이름 재입력·사유 입력 없이 즉시 실행합니다. 이름/전화번호/로그인 계정은 삭제하지 않습니다.
- 초기화 직전 인증·보상·응모 상태와 관리자 세션 ID와 자동 기록 문구를 `admin_audit`에 같은 트랜잭션으로 저장합니다.
- 수강 인증을 지워 2개/4개 미만이 되면 선물/응모 자격을 해제합니다. 응모권은 삭제하거나 번호를 재사용하지 않고 `voided_at`으로 취소 처리합니다. 4개 재인증 후 다시 응모하면 이전 번호를 복구합니다.
- **추첨 시에는 `voided_at IS NULL`인 번호만 유효합니다.** 번호 범위는 `MAX(number)`까지이며, 1~N에서 추첨 시 취소된 번호는 제외하거나 재추첨해야 합니다. 유효 인원수 `COUNT(*) WHERE voided_at IS NULL`를 번호 상한으로 사용하면 안 됩니다.
- 두 앱은 동일한 D1 DB와 로컬 `.wrangler/state`를 사용합니다. 운영 적용 전 최신 마이그레이션을 적용합니다. 현재 운영에서는 메인 Worker의 `/admin` 경로로 관리자 화면과 API를 제공합니다.

### 인증 성공 모션

NFC 인증 성공 시 중복 인증을 포함해 축하 모션을 표시합니다. `인증 현황 새로고침` 버튼은 인증 내역이 있을 때 최근 인증 세션으로 모션을 재생합니다. 브라우저 새로고침·페이지 재접속, 인증 실패, 인증 내역이 없는 경우에는 표시하지 않습니다. `prefers-reduced-motion` 환경에서는 움직임 없이 결과를 안내합니다.

## 성능 개선

- 주요 사진과 장식 이미지는 WebP 정적 파일로 제공합니다. 별도 이미지 변환 바인딩은 사용하지 않습니다.
- NFC 인증은 로그인 조회를 포함해 D1 호출 3회로 처리합니다. 인증·보상 저장과 결과 조회는 한 트랜잭션으로 묶습니다.
- 로그인 입력은 실제 수신 바이트 기준 1KB까지만 읽습니다.
- 관리자 이력은 참가자 ID·생성 시각 인덱스로 조회합니다 (`0007`).
- 관리자 로그인 성공은 실패 횟수에 포함하지 않으며, 같은 Wi-Fi의 실패 횟수 때문에 올바른 비밀번호가 차단되지 않습니다.

- 참가자 화면은 브라우저에 저장한 프로필을 재사용합니다. 캐시가 있으면 페이지 이동·새로고침·재방문 시 `/api/registration` GET을 호출하지 않습니다. 캐시가 없거나 손상되었을 때만 쿠키로 복구하며, 같은 페이지 실행 중 중복 복구 요청은 합칩니다.
- 프로필 캐시는 화면 표시용입니다. 수강·선물·응모 API는 기존처럼 서버 쿠키로 참가자를 확인합니다. 401 응답이면 캐시를 지우고 다시 로그인하도록 안내하며, 대기 중인 NFC 링크는 유지합니다. 다른 탭의 로그인·로그아웃 변경도 반영합니다.

- 관리자 모바일 화면은 참가자 목록을 카드로 표시하고, 선택 시 상세 화면으로 전환합니다. 목록으로 돌아오면 기존 스크롤 위치를 복원합니다.
